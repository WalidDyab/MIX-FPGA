CHANGES MADE BY MIX-FPGA TO UPSTREAM CONTENT

MIX-FPGA patches and rebuilds no third-party program. The only changes to the official release content are:

  - Removed the VHDL-87 and VHDL-93 IEEE libraries (lib/ghdl/ieee/v87, lib/ghdl/ieee/v93 and lib/ghdl/src/ieee): they contain the IEEE 1076.3-1995 numeric_bit and numeric_std sources, which may be distributed only unchanged and not sold or distributed for profit.
  - Removed the VITAL-95 and VITAL-2000 packages (lib/ghdl/src/vital95, lib/ghdl/src/vital2000) and the UPF package (lib/ghdl/src/upf), whose licence is not established.
  - Regenerated the GHDL 2008 and 2019 IEEE library indexes (lib/ghdl/ieee/v08/ieee-obj08.cf, lib/ghdl/ieee/v19/ieee-obj19.cf) with GHDL itself, using the upstream rules of libraries/Makefile.inc without the removed packages (scripts/toolchain/ghdl-prune.mjs); the analysis timestamps of the upstream release are kept.
  - Removed the GHDL plugin-development headers include/ghdl/vpi_user.h, synth_gates.h and synth.h: vpi_user.h and synth_gates.h carry no licence statement, nothing uses them at run time (they are only needed to compile a GHDL plugin), and synth.h includes synth_gates.h.
  - Added the licence texts of the libraries compiled into the yosys executable, and the licence texts that the Toolchain 1.0 notices marked MISSING (libffi, libwinpthread) or described wrongly (termcap is GPL-2.0-or-later, not MIT-style).
  - MIX-FPGA always runs GHDL with --std=08. A design that uses the removed packages gets a normal "unit not found" error.

YOUR RIGHT TO MODIFY AND REPLACE COMPONENTS

The GPL and LGPL components (GNU Readline, GNU termcap, libghw) are separate DLL files, loaded at run time. You may replace them with your own builds made from the corresponding source, which is in the source package, for your own use, and reverse-engineer them for debugging. The installed files are ordinary files in your own user folder: replace a file and keep using the toolchain; nothing has to be signed on Windows. The tools keep working with replaced files.
If you change a file of the installed toolchain, MIX-FPGA reports the toolchain as modified and unverified: "This toolchain has been modified and is no longer the verified MIX-FPGA configuration. You can continue using it, or choose Repair to restore the supported version."
  - MIX-FPGA does not silently overwrite or delete your changes; it only reads the files to report their state (Setup, Verify).
  - You may continue using the modified toolchain: creating projects, checking, simulating, building and programming all keep working.
  - Repair is optional and explicit: it asks first, and then restores the supported MIX-FPGA release copy of the files that differ.
  - A missing or unusable part is reported as needing repair, not as modified.
The integrity check is a support aid, not a technical restriction. A configuration with changed files is not the verified one and is not supported.

5. COMPLIANCE DECISIONS (all resolved)

L1 [resolved] IEEE 1076.3-1995 packages: 'may not be sold or distributed for profit'
    RESOLUTION: Removed in Toolchain 1.1: the VHDL-87/93 IEEE libraries (with the IEEE 1076.3-1995 numeric_bit/numeric_std packages) are no longer shipped. MIX-FPGA runs only --std=08 (core/vhdl/ghdl/ghdl-provider.ts, the same code on Windows and macOS).

L2 [resolved] VITAL and UPF packages have no licence statement in their files
    RESOLUTION: Removed in Toolchain 1.1; the 2008/2019 library indexes were regenerated by GHDL itself.

L3 [resolved] Yosys is distributed linked with GPL-3.0-or-later Readline (and GPL-2.0-or-later termcap)
    RESOLUTION: Technically resolved (Phase 5H, Windows): each program that loads Readline is distributed with it under GPL version 3 with the GPLv3 text, the complete Corresponding Source of both (the pinned Yosys source and the Fedora source packages of mingw64-readline 8.2-3.fc39 and mingw64-termcap 1.3.1-34.fc39) and the build recipe in the source package; Readline and termcap stay separate, replaceable DLL files. The Windows footprint was established from the import tables of all 571 PE files of the toolchain (only yosys.exe and vvp.exe load Readline; none loads it through Python).

L4 [resolved] Yosys source of the exact binary, and notices of libraries compiled into it
    RESOLUTION: Technically resolved: the same pinned commit as macOS (66306a8c with the abc and cxxopts submodules), the YosysHQ recipe that explains the -dirty suffix, and the licence texts of the libraries compiled into Yosys are in the source package and notices. The Windows binary is the unmodified YosysHQ release file; a bit-identical rebuild is not claimed.

L6 [resolved] GHDL build recipe and GCC/GNAT runtime origin
    RESOLUTION: Recorded: the official GHDL release ghdl-mcode-6.0.0-ucrt64.zip, built by GHDL's CI from tag v6.0.0 on MSYS2 UCRT64 with GNAT 15.2.0 (the GCC Runtime Library Exception applies to libgnat and libgcc_s).

L7 [resolved] Does GHDL's GPL reach students' simulation output?
    RESOLUTION: MIX-FPGA runs simulations in memory and distributes no student executables; the notices tell students that an executable produced with GHDL needs its VHDL sources if distributed.

L8 [resolved] Headers without a licence statement (vpi_user.h, synth_gates.h)
    RESOLUTION: Removed in Toolchain 1.1 together with synth.h, which includes one of them; nothing uses them.

L9 [resolved] Integrity enforcement versus the right to replace LGPL/GPL libraries
    RESOLUTION: Resolved by behaviour (Phase 5D, implemented for Windows in Phase 5H): a changed but complete toolchain is reported as installed but modified and stays fully usable; nothing is restored unless the student chooses Repair; missing or broken files are a repair case.
