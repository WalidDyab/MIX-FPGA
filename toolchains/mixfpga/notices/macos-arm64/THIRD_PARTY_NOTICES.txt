5. OPEN QUESTIONS

L1 [needs-decision] IEEE 1076.3-1995 packages: 'may not be sold or distributed for profit'
    GHDL ships the VHDL-87/93 numeric_bit and numeric_std sources (and their compiled form) under IEEE's 1995 terms: distributable unchanged, not for profit. Every student using numeric_std with --std=87/93 relies on them. MIX-FPGA ships them unmodified. Whether free classroom distribution, and any future paid or bundled distribution, is compatible is a legal question. This was not recorded by the earlier NexysVHDL review.

L2 [needs-decision] VITAL and UPF packages have no licence statement in their files
    vital95, vital2000 (IEEE 1076.4 origin) and upf carry no copyright/licence header. Their licence is not established by the payload.

L3 [needs-decision] Yosys is distributed linked with GPL-3.0-or-later readline
    The yosys executable loads libreadline (GPLv3). Treating the combined program as GPLv3 means providing GPLv3 text and the complete corresponding source of yosys and readline, with the libraries replaceable. The earlier review reached the same conclusion for the NexysVHDL bundle. Confirm this position; the alternative (a Yosys without readline) would change a binary and is not done.

L4 [needs-decision] Yosys source of the exact binary, and notices of libraries compiled into it
    The version string ends in '-dirty' (built with local changes), so the pinned commit may not be the exact corresponding source. Third-party code compiled into Yosys (minisat/ezsat, json11, fstapi, …) has notices that are not in the payload.

L5 [minor] libusb text shipped in the payload is a 1.0.24 revision, the library is 1.0.26
    license/LICENSE.libusb in the payload records the 1.0.24 revision; the shipped library is the MacPorts 1.0.26 build. The 1.0.26 COPYING is added next to it. Both are LGPL-2.1.

L6 [minor] GHDL build recipe and GCC/GNAT runtime origin not fully recorded
    GHDL's corresponding source is pinned to its revision, but how this LLVM build was produced (build scripts) and the exact GCC/GNAT runtime build are only partly recorded. No source is required for the runtime by the GCC exception.

L7 [minor] Does GHDL's GPL reach students' simulation output?
    The GHDL std library sources are GPL-2.0-or-later with no exception statement in the files. GHDL's own position on generated simulations should be located and recorded.

L8 [minor] Headers without a licence statement (vpi_user.h, synth_gates.h)
    See the components vpi-header and ghdl-gpl-headers.

L9 [needs-decision] Integrity enforcement versus the right to replace LGPL/GPL libraries
    libusb, libftdi1 and libghw (LGPL), readline (GPLv3) are separate replaceable files, but the installed toolchain is read-only and MIX-FPGA's integrity check reports a replaced file as damaged and restores it. A recipient who wants to run a modified library must be able to. The source offer should describe how (for example running the tools by hand from a copy), and counsel should confirm the design.

L10 [needs-decision] openFPGALoader bridge bitstreams: provenance
    111 prebuilt FPGA bitstreams built with vendor tools; no per-file provenance or vendor-IP statement in the release. Unused by MIX-FPGA's flows.

L11 [minor] Lima third-party licences: collected; one MPL-2.0 module needs a source pointer
    Licence texts for the Go standard library and all 100 Go modules were collected from the exact versions embedded in the Lima binaries (all 100 archive hashes match the hashes embedded in the binaries). github.com/hashicorp/hcl/v2 is MPL-2.0: the release notices must say how to obtain its source (the pinned archive is recorded). Remaining items are legal-review matters (NOTICE and PATENTS files).
