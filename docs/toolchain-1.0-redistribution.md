# NexysVHDL Toolchain 1.0 — redistribution and license review

This document records the redistribution/license review of NexysVHDL Toolchain 1.0 for **Windows x64 (`win32-x64`)** and **macOS Apple silicon (`darwin-arm64`)**: what is redistributed, under which license, where the corresponding source is, what changed, and what is still open. It is an engineering record of evidence, not legal advice; nothing here is a legal opinion on a license.

**Status**

- Software/runtime: **READY** (Windows re-validated after this review's payload change; macOS unchanged).
- Redistribution/license: **NOT READY** — 6 blocking open items (§8). The corresponding-source package can be built, reproducibly, but only as a *draft*.
- Physical Program: **DEFERRED** (no Nexys A7 board attached during this review; Digilent detection only).

Machine-readable record: [`toolchains/compliance/toolchain-1.0.json`](../toolchains/compliance/toolchain-1.0.json) (generated by `npm run compliance:manifest` from the recipes, `toolchains/compliance/curation.json` and the evidence inventories). Source archive hashes: [`toolchains/compliance/sources-1.0.lock.json`](../toolchains/compliance/sources-1.0.lock.json).

## 1. Principles

- **Aggregation, not relicensing.** Toolchain 1.0 is an aggregation of separate third-party programs and data, each under its own license. It is **not** licensed under NexysVHDL's Apache License 2.0. The Apache License 2.0 (Copyright 2026 Walid Dyab; NexysVHDL is an EMXplore project) covers NexysVHDL's own code and the NexysVHDL-authored files inside the toolchain: `toolchain-manifest.json`, `THIRD_PARTY_NOTICES.md`, the pinned Apio remote configuration, `apio/packages/installed_packages.json`, the Python shim and the placeholder notes.
- **Unmodified.** NexysVHDL redistributes official upstream release archives (pinned URL + SHA-256), extracted unmodified. It applies no patches and rebuilds nothing (`patches/` in the source package is empty by design). The only change to upstream content is *omission*: two unused Apio packages are replaced by empty placeholder folders (§5).
- **Evidence over memory.** Licenses were identified from the license texts shipped in each archive (`scripts/compliance/inventory.mjs`), upstream repositories at the recorded commits, PyPI metadata, PE import tables (`scripts/compliance/pe-imports.mjs`), PyInstaller archive tables of contents and process traces. Where the evidence is missing, the item is recorded as open (§8), not assumed.
- **Digilent:** not redistributed, mirrored or downloaded (§7).

## 4. Corresponding source: `NexysVHDL-Toolchain-1.0-Sources.zip`

**Design.** One package for both platforms (Windows and macOS share most source revisions: GHDL v6.0.0, the same oss-cad-suite tool revisions, Apio definitions), published as a release asset next to each NexysVHDL release that includes Toolchain 1.0 — "from the same place" as the binaries. Never committed to Git; generated under `.artifacts/compliance/` (ignored).

**Contents.**

```
NexysVHDL-Toolchain-1.0-Sources.zip
  README.md          what the package is, the source table, open items (draft only)
  manifest.json      the compliance manifest + SHA-256 of every source archive
  sources/           one .tar.gz per pinned source and per git submodule
  licenses/shared/   the license texts shipped in both toolchains
  licenses/darwin-arm64/
  patches/README.md  "no patches" (NexysVHDL modifies no third-party source)
  nexysvhdl/         NexysVHDL's LICENSE and NOTICE (not applicable to the third-party parts)
```

**Pinned sources (30, producing 48 archives).** GHDL v6.0.0 (`e589c698…`); Apio 1.6.0 (`9fbb279c…`) and 1.7.0 (`ccede3ec…`); apio-definitions (`2fd2c665…`); the FPGAwars build recipes of the oss-cad-suite (`b246ed02…`) and openXC7 packages (Windows `8a01b11b…`, macOS `22b6a11d…`); YosysHQ oss-cad-suite-build at release tag 2026-03-24 (`ac8c7dba…`); every GPL/LGPL/EPL/EUPL tool of the oss-cad-suite at the revision its `license/LICENSE.<tool>` file records (dfu-util, GTKWave, Icarus Verilog, libftdi, libpoly, libusb, OpenOCD + 3 submodules, Surfer ×2 + 2 submodules each, Verilator, Yices; macOS also black-iceprog, ghdl-yosys-plugin, Graphviz + 11 submodules, icefunprog, TinyFPGA B, tinyprog, xdot); mcfgthread v1.6-ga.1 (`40263a6e…`); PyPI sdists of certifi 2026.07.22, vcdvcd 2.6.0 and pycairo 1.25.1 (by SHA-256).

**Build.** `npm run compliance:assemble` fetches each git source *by exact commit* (never a branch, tag or "latest") into a cache, follows submodules at the commits recorded in the tree, and writes `git archive` tarballs gzip-compressed without timestamps; PyPI sdists are downloaded from the pinned URL and must match the pinned SHA-256 and size. Every archive must match `sources-1.0.lock.json` (`--record` rewrites it). The command **fails** while any blocking item is open; `--draft` builds `NexysVHDL-Toolchain-1.0-Sources-DRAFT.zip` for review instead (marked as a draft inside; must not be published).

**Reproducibility (verified).** The draft was built four times (the first online with `--record`, the others offline from the cache): every run matched all 30 sources in the lock, and runs with the same manifest gave byte-identical zips. Final draft (with the final compliance manifest): 70 files, 139.6 MiB, SHA-256 `577361b2d64f389c7f5798abdb3dd3093ccfd75c8611a769bcde9b3984279770` (git 2.53.0, Node 24.13.0). The lock records the tool versions; another git/zlib version could produce different (equally valid) archive bytes, which the lock check reports.

## 5. Windows payload change: drivers and graphviz become placeholders

Apio 1.6.0 refuses to run any command unless every package listed for the platform in `apio/resources/packages.jsonc` is installed; on Windows that includes *drivers* and *graphviz*. NexysVHDL never uses either:

- **drivers** (`apio drivers …`): Zadig, `lsusb`, `lsftdi`, `ftdi_eeprom` and **`serial_install.exe`**. `serial_install.exe` is PJRC's "Serial Installer" for Teensy boards ((C) 2014 PJRC.COM, LLC; Comodo-signed), committed as a prebuilt binary to FPGAwars/tools-drivers without any license file: **redistribution terms unknown**. NexysVHDL installs no USB drivers (Windows programming uses the official Digilent software).
- **graphviz** (`apio graph`): the official Graphviz 12.1.2 Windows build (EPL-1.0, upstream `LICENSE` at tag 12.1.2), shipped without any license file and with the Microsoft VC++ runtime. NexysVHDL's RTL Schematic uses Yosys JSON and its own renderer.

Evidence (also in `toolchains/bundle/win32-x64.json`, `placeholder.evidence`): `packages.jsonc` at Apio `9fbb279c`; a PE import scan of all 655 PE files of the payload (no used file imports a DLL that only these packages provide — the only importer of `msvcp140.dll` is the unused verible package); process traces of the installed-VSIX workflow (none of `zadig`, `lsusb`, `lsftdi`, `ftdi_eeprom`, `serial_install`, `dot` ever ran); and an offline experiment in which Apio 1.6.0, with empty folders and matching `installed_packages.json` entries, reported all packages installed and ran with network access blocked.

**Smallest recipe change.** The two components became `placeholder` entries (no archive; reason, evidence and the identity of the upstream package kept under `notRedistributed`). The assembler creates the folder with a `NEXYSVHDL-PLACEHOLDER.txt` note; `installed_packages.json` keeps the pinned release version, with `loaded-from: nexysvhdl-placeholder:<archive> (not redistributed; unused by NexysVHDL)`. The Graphviz and libwdi license texts moved from the shared `licenses/` to `licenses-darwin-arm64/`, so Windows no longer ships them while the macOS payload keeps exactly the same files.

**Result.** Every other component is byte-identical (same per-component tree hashes). Windows Toolchain 1.0 content: 21,465 files / 3,170,712,308 B / tree `43b3fb80d30f7f87a61364ce636a57da1dcfd44ee07033746ca5854f133eaef9` → **21,208 files / 3,141,371,862 B / tree `57f0f0da89e6565d6e46d20780fa57af86f8ac36d45a78b750203fc8f381820b`** (archive 709.6 MiB, SHA-256 `83aeb26539fbd2d4a2aabd0c53015011bb9655da1b8cbfcdde9d841ce5508315`). `requirement.json` was updated deliberately. Lifecycle rule (ADR-007 §6): toolchain payloads become immutable at release freeze / external distribution; before the first external release, internal validation candidates for that version may be replaced; after release, any payload change requires a new toolchain version. Toolchain 1.0 had not been distributed externally, so `43b3fb80…` was an internal pre-release validation candidate and `57f0f0da…` is the Windows Toolchain 1.0 pre-release payload. The runtime integrity rule is unchanged: an installed 1.0 with any other hash (including `43b3fb80…`) is reported as `TOOLCHAIN_VERSION_CONFLICT` and never modified in place (test in `tests/toolchain-bundle.test.ts`).

**Re-validation (installed VSIX, 2026-10-03).** `nexysvhdl-0.5.0-win32-x64.vsix` installed into a private VS Code profile with a private `LOCALAPPDATA`, PATH reduced to the OS folders and hostile `APIO_HOME`/`PYTHONPATH`/`NEXYSVHDL_GHDL` (driver `tests/integration/run-installed.ts`):

## 6. Per-component findings

- **GHDL (Windows):** official `ghdl-mcode-6.0.0-ucrt64.zip`; GPL-2.0-or-later; ships MSYS2 runtime `libgnat-15.dll`, `libgcc_s_seh-1.dll` (GCC 15.2.0 Rev13; GCC Runtime Library Exception), `libwinpthread-1.dll` (MIT/BSD), `zlib1.dll` (Zlib). Source: GHDL v6.0.0 in the package. Ready.
- **GHDL (macOS):** `ghdl-llvm-jit-6.0.0-macos15-aarch64`; LLVM 22.1.0 linked statically (Apache-2.0 WITH LLVM-exception); `libgnat-14`, `libgcc_s` under the exception. Ready (non-blocking note: exact GCC 14 build not recorded).
- **Apio:** GPL-3.0-or-later — evidence: the bundled `LICENSE` is the GPLv3 text, Apio 1.6.0's `pyproject.toml` classifier is "GPLv3 or later", Apio 1.7.0 declares `license = "GPL-3.0-or-later"`. Earlier NexysVHDL records said "GPL-2.0": **corrected** (Windows payload notices regenerated; macOS payload label unchanged, §9).
- **Python in Apio:** Python 3.14 (PSF-2.0) with 28 third-party packages; copyleft-type ones: certifi 2026.07.22 (MPL-2.0), vcdvcd 2.6.0 (Perl terms: Artistic-1.0 or GPL-1.0-or-later, plus MIT) — sdists included. Versions not recorded in the bundle for idna, jsonschema-specifications, referencing, rpds-py, setuptools, urllib3, pyusb (all permissive; listed as such).
- **Yosys / nextpnr / openXC7 / Project X-Ray:** ISC (Yosys, nextpnr, nextpnr-xilinx, Project X-Ray tools), CC0-1.0 (prjxray-db and the generated chip database). No source obligation; texts shipped.
- **openFPGALoader 1.1.1 (macOS):** Apache-2.0; loads libusb (LGPL-2.1, source in package), libftdi (LGPL-2.0 library / GPL-2.0 tools, source in package) and hidapi from the package.
- **libusb / libftdi / hidapi:** sources at the recorded revisions included; hidapi is offered under a choice of licenses.
- **Qt (macOS):** 60 Qt 5.15.3 frameworks shipped by the oss-cad-suite package without any license file (LGPL-3.0); used by GUI tools NexysVHDL does not run. Source build not recorded upstream — open item.
- **OpenSSL:** Windows Apio bundle `libssl-3`/`libcrypto-3` (OpenSSL 3, Apache-2.0); macOS Apio OpenSSL 3.5.7 (Apache-2.0). Permissive.
- **Graphviz:** Windows: not redistributed any more. macOS: the oss-cad-suite package includes Graphviz (EPL-1.0) — source included.
- **Digilent:** see §7.

## 7. Digilent

Unchanged policy: NexysVHDL does not include, mirror or download Digilent Adept Runtime, Adept Utilities (`djtgcfg`) or Digilent drivers. On Windows it detects the student's official installation and points to <https://digilent.com/reference/software/adept/start>. Not a redistribution blocker: nothing of Digilent's is redistributed. On macOS openFPGALoader (in the toolchain) programs the board; no Digilent software is needed.

## 8. Open items

Blocking (`Redistribution/license` stays **NOT READY** until each is closed):

1. **win32-oss-cad-suite-fedora-mingw-libraries** — 161 Fedora 39 MinGW DLLs in the Windows oss-cad-suite package (Qt 5.15.11, GTK 3.24.38, GLib 2.77.1, GNU readline 8 + history (GPL-3.0, loaded by Yosys), gettext/libintl, iconv, libtermcap, OpenSSL 3.0.9, Python 3.11.6, …) without a recorded package build, so their exact source (Fedora SRPMs) cannot be pinned.
2. **win32-apio-microsoft-runtime** — Microsoft VC++/UCRT runtime DLLs in the Windows Apio bundle: redistribution terms need review.
3. **win32-openxc7-msys2-runtime** — `libmcfgthread-1.dll` (LGPL-3.0-or-later): upstream v1.6-ga.1 source is included, but the MSYS2 package release (and any patches) is not recorded.
4. **darwin-oss-cad-suite-bundled-libraries** — Qt 5.15.3 frameworks and ~75 dylibs (GTK, GLib, GMP, readline, gdbm, libiconv, …) in the macOS oss-cad-suite without recorded builds.
5. **darwin-openxc7-nix-libraries** — Nix-built libraries in the macOS openXC7 package (libiconv/libcharset LGPL) without a recorded nixpkgs revision.
6. **darwin-apio-bundled-libraries** — libusb-1.0 (LGPL-2.1) in the macOS Apio bundle: version not recorded.

Non-blocking: **darwin-ghdl-gnat-runtime** (record the exact GCC 14 build), **surfer-rust-dependencies** (Surfer's crates are not vendored; EUPL-1.2 art. 5 allows indicating the repository; `cargo vendor` at the pinned revision would make the package self-contained).

Resolution paths for 1, 3–6: map each library to its exact build input and add its source; or ask the original distributor (YosysHQ, FPGAwars) for the corresponding source/build manifest; or, for Toolchain 1.1, prune the payload to the files the Nexys A7 flow uses (Yosys and its runtime closure, nextpnr-xilinx, Project X-Ray tools, openFPGALoader on macOS) so far fewer libraries remain to resolve. Resolution for 2: legal review of Microsoft's redistributable terms, or an Apio build that relies on the OS-provided UCRT.

## 9. macOS follow-ups (for the Mac; the darwin-arm64 payload was not touched from Windows)

The validated macOS Toolchain 1.0 (tree `f04022180f9bb746dc5dc467bc7d1d379512f302159763f8c4a8c0ed50b2aac7`) is unchanged: its recipe is byte-identical and the license texts it ships are the same files (now partly kept in `licenses-darwin-arm64/`). Corrections that would change Mac content are recorded here and in the compliance manifest instead:

1. The Mac payload notices label Apio and the definitions "GPL-2.0"; correct is GPL-3.0-or-later / GPL-3.0. Fix in the next Mac toolchain version (or a deliberate Mac re-validation): correct `toolchains/bundle/darwin-arm64.json` licenses, add the `compliance` block, re-assemble on the Mac, re-validate, update `requirement.json`.
2. `licenses-darwin-arm64/graphviz-LICENSE.txt` is the EPL-2.0 text; the macOS Graphviz is EPL-1.0 (its correct text is already in `apio/packages/oss-cad-suite/license/LICENSE.graphviz`). Replace or drop it in the next Mac version; `libwdi-COPYING.txt` is not needed on macOS.
3. Help close items 4–6 from the Mac: list `otool -L` of the used closure (yosys, openFPGALoader, nextpnr-xilinx, Python) and the Qt dependents; check whether Qt frameworks can be pruned in Toolchain 1.1 (not in 1.0).

## 12. Portability fixes made on this branch

Two cross-platform fixes, independent of the license work, were made first so the test suite passes on both hosts: the classroom PATH test now joins with the host's `path.delimiter`, and the toolchain tar writer (`core/toolchain/tar.ts`, and `scripts/toolchain/lib.mjs`) normalizes Windows-read symbolic-link targets to POSIX form before the same safety checks (relative only, no absolute or drive targets, no `..` escape).
