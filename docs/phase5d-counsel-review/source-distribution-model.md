# Corresponding-source delivery model

What we propose to do, and what the packages contain. Not a legal conclusion. Hashes of the files named here: [EVIDENCE-SHA256.txt](EVIDENCE-SHA256.txt).

## 1. Model

- The release has two binary **support archives**, and each is distributed **together with its own complete corresponding-source package** (one source package per archive; shared sources are duplicated on purpose, so each pair is self-contained):

  | Binary archive | SHA-256 | Source package | SHA-256 |
  |---|---|---|---|
  | `nexysvhdl-toolchain-1.1-darwin-arm64.tar.gz` (Nexys A7 support; 652,947,482 bytes; 31,541 files) | `6fc1f3ad3f0343fc04b2e270f669824db30f84bf71b91bd38640482f20433f0f` | `MIX-FPGA-Nexys-A7-Support-1.1-Sources.zip` (490,733,519 bytes; 238 files; 135 source archives) | `5ccdc8f3f9389945fc9500a0dd24e871aa9d36d568567b140e229db5d867c2e1` |
  | `mixfpga-de10-lite-support-1.1-macos-arm64.tar.gz` (DE10-Lite support; 88,871,550 bytes; 683 files) | `25317169b9bab2a636cf5cf420238eab43ad2c955dd82acddcf566244b3f6aa2` | `MIX-FPGA-DE10-Lite-Support-1.1-Sources.zip` (24,365,760 bytes; 178 files; 13 source archives) | `8c76974eb5cf91c2ad79743bcf59739fdb7ede7933fd756412078494563824fa` |

- Both pairs are hash-pinned: the extension pins each archive by name, size and SHA-256 (`toolchains/mixfpga/payloads-1.1.json`); the DE10-Lite archive is verified against its SHA-256 before extraction and every file of both archives is verified against the recorded content hashes after extraction; each archive's own notices name the source package that goes with it; each source package lists its target archive's SHA-256 in its `manifest.json` (`forArchive`).
- The package is delivered at the same place and time as the archive: the same download location / course-materials folder holds both files, side by side, and a classroom mirror must copy both. The source package stays available for as long as the archive is offered. **We do not rely on a written offer.** (The concrete hosting location is not decided yet; the commitment above is the intended model.)
- The student receives the pair from the course (the course provides the support files; the extension asks for the file and checks it).

## 2. What a source package contains

| Path | Content |
|---|---|
| `sources/` | the exact upstream source archives of every component whose licence requires source (GNU GPL, GNU LGPL, MPL, EPL, EUPL), each pinned by SHA-256; git sources are `git archive` of the exact commit with submodules at the recorded commits; the MPL-2.0 Go module is the original module archive from the Go module proxy (`github.com_hashicorp_hcl_v2@v2.24.0.zip`, sha256 `53fd4e96ac9c190e192759daf49b63397865214d337ab5f6dbf6e68c1b0f4810`, equal to the go.sum-verified hash recorded in `go-licenses.json`) |
| `licenses/` | the licence texts and notices shipped in the archive, plus the texts of bundled libraries the archive itself does not carry |
| `THIRD_PARTY_NOTICES` | the notices of the archive |
| `mix-fpga-build/` | MIX-FPGA's build recipe (Nexys: `darwin-arm64-1.1.json`; DE10: inventory and assembler), the one MIX-FPGA tool that changes upstream content (`ghdl-prune.mjs`), the toolchain manifest, `yosys-rebuild-evidence.md` |
| `patches/README.md` | MIX-FPGA modifies **no third-party source and applies no patches**; the binaries are the official upstream releases. The only changes to upstream content are omissions and regenerated index files listed in the notices and in `binary-to-source.json` under `modifications` |
| `binary-to-source.json` | mapping from every shipped component and (Nexys) library group to its source archives, with hashes |
| `manifest.json` | SHA-256 and size of every file of the package (the manifest itself excepted) and the list of source archives |
| `mix-fpga/` | MIX-FPGA's own licence (Apache-2.0) and NOTICE |
| `README.md` | what the package is, what is not included, how to check hashes |

Both packages were rebuilt twice with identical hashes, pass `unzip -t`, and every file hash in each `manifest.json` was re-verified after extraction.

**Nexys A7 package, by licence family** (from its manifest): 88 GPL/LGPL-family source archives, 18 MPL/EPL/EUPL, 26 permissive or other, 3 other (135 in total). **DE10-Lite package:** GHDL 6.0.0; Yosys with its `abc` and `cxxopts` submodules and the YosysHQ build recipe; GNU Readline 8.2 with patch 001 and its MacPorts port; libusb 1.0.26 and libftdi1 1.5 with their MacPorts ports; the `hcl` module.

## 3. Changes MIX-FPGA made to upstream content (listed in the notices of each archive)

Removed: the VHDL-87/93 IEEE libraries (including the IEEE 1076.3-1995 packages), VITAL-95, VITAL-2000, UPF, the 111 openFPGALoader bridge bitstreams, three GHDL plugin-development headers (`vpi_user.h`, `synth_gates.h`, `synth.h`), and in the Nexys archive two wrong licence texts. Regenerated by GHDL itself: the 2008 and 2019 IEEE library index files. Added: licence texts, Lima's NOTICE. Nothing else differs from the official archives (verified file by file against Toolchain 1.0).

## 4. Not in the packages

- Permissive components that need no source (openFPGALoader, Lima, LLVM, zlib, zstd, hidapi, libffi, Tcl, ncurses, and in the Nexys archive Python, OpenSSL, Boost, ICU and similar): their upstream revisions are recorded in `binary-to-source.json`, their licence texts are in `licenses/`.
- Windows sources (not part of this macOS release); Altera Quartus (supplied by the student from Altera), Apple Rosetta and macOS, Canonical's Ubuntu image (downloaded on the student's computer): never part of any MIX-FPGA download.
- MIX-FPGA's own source code (Apache-2.0) is not part of these packages.
